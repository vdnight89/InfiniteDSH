# Code review — InfiniteDSH (2026-08-16)

Follow-up (same day): all issues below are fixed in **0.3.0**. `/export` is now `/export-story`; `NO_PROVIDER` degrades; plots/style cards no longer leak into world rules; `/cast` and `/bind` match the spec; covers are original.

Working-tree review of a brand-new repo (no commits). Compared `packages/infinite-core`, `packages/dsh-infinite`, `packages/dsh-infinite-preset`, and the locked spec in `docs/superpowers/specs/2026-08-16-dsh-infinite-design.md` plus later requests (AskUserQuestion cards, AIRP port, whale-lab template). DSH 0.1.0-rc.5 APIs were checked in the sibling tree `F:\DocProject\deepseek-harness` only to confirm host contracts.

## Summary

The split is right: `infinite-core` is testable, `/new` copies a session-local tree, literary context is gated on `meta.yml`, and the whale-lab / AIRP template set is present. The documented `dsh --profile infinite web` path is not: host command `export` collides with DSH Web’s built-in `/export`, and `canAsk()` treats the always-on `userQuestions` service as a UI. World-rule assembly still swallows plot seeds (including cross-genre openings), imported style cards are the literal string `undefined`, and `/cast` leaves the template’s constant hero in place.

## Issues

### Issue 1 -- Severity: bug
- File: packages/dsh-infinite/src/commands.ts:296
- Description: The plugin registers a global host command named `export`. DSH Web already mounts `@deepseek-ai/dsh-session-log-export`, whose host half also registers `/export` (ZIP download). `ctx.commands.register` throws `command "export" is already registered` on a duplicate global name. `apply()` calls `registerCommands` before `registerPrompt` and the `session/event` hook, and those `register()` calls are not wrapped in `ctx.effect`, so a throw on the fourth command can abort literary prompt/lifecycle setup while leaving `/new` `/bind` `/cast` registered. The README path `dsh --profile infinite web` is the collision case. Headless (no session-log-export) is unaffected.
- Suggestion: Do not steal the Web command. Register `/export-story` (or another unused name), or only claim `export` when the name is free and document that Web keeps `/export` for the ZIP. Wrap every `commands.register` / `ctx.on` in `ctx.effect` so a failed `apply()` rolls back.
- Status: fixed in 0.3.0

### Issue 2 -- Severity: bug
- File: packages/dsh-infinite/src/ask.ts:3
- Description: `canAsk()` is `typeof ctx.userQuestions?.ask === 'function'`. Base DSH always provides that service; `ask()` only throws `NO_PROVIDER` when no UI provider is registered. Headless therefore looks like it can ask. Bare `/new` and even `/new 修仙` (which still asks protagonist and opening when `canAsk` is true) call `askUser` and throw instead of using defaults. README says a topic argument is enough in headless. `handleNew` does not catch this. Tests never install a service-without-provider stub, so they miss it.
- Suggestion: Treat `NO_PROVIDER` (and missing provider) as “no UI”: skip asks and keep `/new <题材>` working with template defaults. Do not require a successful `ask()` to finish a fully specified command.
- Status: fixed in 0.3.0

### Issue 3 -- Severity: bug
- File: packages/dsh-infinite/src/story-files.ts:66
- Description: `loadWorldbook` concatenates `worldbook/*.md` and `plots/*.md`. Prompt assembly (`prompt.ts`) feeds that list to `buildWorldContext`, so unused opening seeds are keyword-matched as 【世界规则】. The importer also drops other-genre seeds into a book (e.g. `packages/dsh-infinite-preset/templates/cultivation/plots/all-apocalypse-corpse.md` is an 末世 opening about 尸潮). Mid-story text that hits keys such as `挑战` / `尸潮` injects another book’s 【开局·…】 blurb into this session. Random-event picking now filters `剧情` / `开篇` / `写法`; world-rule injection does not. Cross-session isolation tests still pass because each session has its own directory.
- Suggestion: Keep plots out of `loadWorldbook`. Only the chosen `opening.md` should be a constant lore entry. Re-run or fix the importer so cultivation does not receive apocalypse/scifi seeds.
- Status: fixed in 0.3.0

### Issue 4 -- Severity: bug
- File: scripts/import-airp-presets.mjs:388
- Description: Style cards are written from `style.name`, `style.tags`, `style.description`, `style.systemPrompt`. AIRP `PromptTemplate` fields are `title` and `content` (see airp-desktop `src/lib/db.ts` builtins). Every shipped template therefore has eight `worldbook/style-tpl-*.md` files whose title/keys/body are the literal `undefined` (example: `packages/dsh-infinite-preset/templates/cultivation/worldbook/style-tpl-opening.md`). They are copied into every session. They are excluded from random events by category, but they are dead weight and will inject `undefined。undefined` if the transcript ever contains the token `undefined`.
- Suggestion: Map `title`/`content` (and skip or key off real tags). Delete the broken `style-tpl-*.md` files from all templates and regenerate. Add a test that no lore file has `title: undefined`.
- Status: fixed in 0.3.0

### Issue 5 -- Severity: bug
- File: packages/dsh-infinite/src/commands.ts:118
- Description: `applyProtagonist` skips writing `protagonist.md` when some card already has that title (so `/new 修仙` no longer doubles 谢无妄). It never demotes the template’s constant default hero. `/new 修仙` then `/cast 江澄` leaves `characters/char-xiewuwang.md` (`constant: true`) beside the new `protagonist.md`. Both are always injected. The same happens if the AskUserQuestion pick is any name other than the template default.
- Suggestion: When the chosen name differs from the template default, set the old default card to `constant: false` (or rewrite it as an NPC). Tests should `/new 修仙` + `/cast 江澄` and assert only 江澄 is constant.
- Status: fixed in 0.3.0

### Issue 6 -- Severity: bug
- File: packages/dsh-infinite/static/cards.js:45
- Description: Card takeover inserts a cover `<img>` as the button’s first child. DSH `QuestionComposer` already rendered `<span class="number">` + `<span class="optionCopy">` (label, badge, description). `cards.css` only hides `span:first-child`, which no longer matches after the insert, so the original label stack stays visible under the new `.infinite-card-copy` title/blurb. Topic and opening pickers therefore show duplicated text. There is no test of the static enhancer against the real AskUserQuestion DOM.
- Suggestion: Hide every original child except the cover and `.infinite-card-copy` (e.g. `button > :not(.infinite-card-cover):not(.infinite-card-copy) { display: none }`), or replace the button contents instead of appending. Add a small DOM test using the real markup shape.
- Status: fixed in 0.3.0

### Issue 7 -- Severity: bug
- File: packages/infinite-core/src/catalog.generated.ts:79
- Description: `scifi` aliases include `赛博`. `cyber` is a later catalog row whose aliases are `赛博朋克` / `义体` / `cyber`. `resolveTemplateId` returns the first hit, so `/new 赛博` opens 科幻, not the 赛博 template README lists as its own topic. The `/new` input hint still says `修仙 | 末世 | 都市`, which has the same class of problem: `都市` resolves to `modern` (现代), not `urban` (都市异能), while the original lock was `都市|urban`.
- Suggestion: Remove `赛博` from the scifi alias list (keep `赛博朋克` on cyber). Decide explicitly whether `都市` means 现代 or 都市异能, then make README, the command hint, and the catalog agree.
- Status: fixed in 0.3.0

### Issue 8 -- Severity: bug
- File: packages/infinite-core/src/export.ts:17
- Description: `cleanProse` rewrites every run of blank lines to a single newline. `/export` is supposed to be the clean literary TXT. Paragraph breaks in the assistant prose are destroyed; the file is a wall of text. The unit test only checks tag stripping, so this passed.
- Suggestion: Strip heading lines and template tags, but keep single blank lines between paragraphs (collapse `\n{3,}` at most).
- Status: fixed in 0.3.0

### Issue 9 -- Severity: bug
- File: packages/dsh-infinite/src/commands.ts:225
- Description: Spec: `/bind [题材]` shows the binding or replaces it, and replacement requires `force`. The no-arg AskUserQuestion path always calls `seedStory(..., true)` after a single “换一本规则书？” pick — no overwrite question, no `force` token. That deletes the session `infinite/` tree (archive, casts, picked events). `/new` asks “覆盖重开”; `/bind` does not. There is no `handleBind` test.
- Suggestion: Reuse the overwrite question (or require an explicit force option) when `hasStory(root)`. Without confirmation, only display the current binding.
- Status: fixed in 0.3.0

### Issue 10 -- Severity: suggestion
- File: packages/dsh-infinite/src/index.ts:20
- Description: F3 says session events record the bind (template id, directory, switches, picked event ids) and must not dump the book into the log. The host only writes `meta.yml`. `pickedEventIds` / `pendingEventId` never become session events. Replay of the same JSONL on another machine without the artifact dir has no story identity. Compaction archive hook itself is the right event name (`compaction/summary` with `data.summary` as content blocks).
- Suggestion: On `/new` `/bind` `/cast` and on turn/end event draw, `session.append` a small `infinite/bind` (or reuse a documented custom type if the host forbids unknown types) with template id, relative dir, guard flags, and the new picked id.
- Status: fixed in 0.3.0

### Issue 11 -- Severity: suggestion
- File: packages/dsh-infinite/src/story-files.ts:114
- Description: Each `compaction/summary` overwrites `archive.md`. DSH’s summary is the shadowed range, not the whole book. Later compactions drop earlier plot notes unless the new summary restates them. M2 only requires “write archive.md”, so this is not a lock violation, but it is a weak literary bible.
- Suggestion: Append dated sections, or merge the new summary under a previous-archive heading.
- Status: fixed in 0.3.0

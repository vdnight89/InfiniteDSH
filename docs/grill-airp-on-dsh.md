## 0. 一句话立场（已按 Q1 修订）

这是一个 **DSH 插件**，不是独立软件，也不移植灵叙的 UI。

树外可安装的 bundle（加文学 preset）。第一期交付引擎：能开一本故事、按规则书写下去、切会话就不串世界、能导出干净正文。书架、封面、阅读器、独立分析模型不做。用户面对的仍是 DSH 的会话 / 工作区 / 斜杠命令。

品牌上不能用「灵叙 / Narra」。内容上灵叙是 MIT，引擎思路可借鉴，内置题材插画与品牌资产不要搬。

## 1. 已经核实的事实（不再问你）

### 1.1 灵叙实际是什么

灵叙不是「聊天套皮」，产品原则是：**家是书架，书是故事，对话是书的内部，作品是导出层。**

核心对象：

```
Story（书）
  └── Volume（卷）= Session
        └── Message（回合）
```

一本故事绑定：规则书、文风预设、主角、题材、世界底座。切书时只信这本书的 `worldBookId`，禁止回落到上一本的全局激活书。

真正让它「能写成小说」而不是闲聊的，是下面这条生成管线（`useChat.buildApiMessages`）：

1. 会话 system prompt  
2. 文风预设  
3. 输出约束：只出正文，不要章节名 / 场景条 / 推荐标签  
4. 可选护栏：叙事防护、剧情推进  
5. 长对话摘要 / 剧情档案 / 旧卷触发片段  
6. **规则书**：常驻条目 + 关键词命中条目（`worldBookEngine`）  
7. 会话临时设定（压缩时抽出，不写回规则书）  
8. 随机世界事件抽卡  
9. 角色卡：触发词命中才注入  
10. 上一轮场景条 + 可选「角色后台进展」（玩家不可见）  
11. 历史消息（assistant 会剥掉旧模板标签，只留正文）

正文生成之后，另开一次模型请求做**格式分析**（章节名、地点、时间、出场、起因、3 条对话推荐、后台进展）。分析失败则场景条与推荐隐藏，不挡正文。

「插件」在灵叙里不是 Cordis 插件，只是设置页开关：叙事防护、剧情推进、角色后台、随机世界事件、独立分析模型。

明确不做：书源 / 发现 / 社交 / 账号 / 多端实时同步。空白稿纸也是书，只是分组叫稿纸。

### 1.2 DSH 实际是什么

DSH 是 Cordis 驱动的 **everything-is-a-plugin** harness，开发者预览，**会破坏兼容**。

新行为必须挂在已有扩展点上，不要改 `agent-loop`：

| 你想做的事 | DSH 机制 |
|---|---|
| 给模型加设定 | `ctx.systemPrompt.section()` 或 `agent.inject()` |
| 给模型加工具 | `ctx.tools.register()` / `restrict()` |
| 人不经过模型下指令 | `ctx.commands`（`/foo`） |
| 持久化业务事实 | 扩展 `SessionEventMap`，遵守「模型可见 ⟺ 已入日志」 |
| 换一套能力组合 | Agent preset（`agent.cordis.yml`） |
| 改 Web 聊天气泡 | Client 插件 + `ConversationNodeDefinition` |
| 分发安装 | `dsh.bundle` + `dsh plugin --profile <name> add` |
| 长上下文 | 已有 `ctx.compaction`，不要重写压缩循环 |

树外插件的正确姿势：独立 npm 包声明 `dsh.bundle`，用户装进自己的 profile，而不是 fork DSH、也不是往 `packages/` 里塞私货。

Web UI 的家是**会话列表 + 编码 Agent 对话**，不是书架。侧栏、模型、权限、工具卡片都按这个假设长出来。

### 1.3 两边最硬的摩擦

1. **产品家不同**：灵叙的家是书架；DSH 的家是会话。  
2. **默认 Agent 不同**：DSH 默认给 bash / 读改文件 / 子代理；文学创作默认不该让模型去改你的磁盘。  
3. **UI 不同**：灵叙是小说排版；DSH 是聊天气泡 + 工具卡片。完整书架 / 阅读器等于再做一个 Client 产品。  
4. **状态模型不同**：灵叙有独立 SQLite（stories / world_books / characters）；DSH 权威状态是 session log + 工作区文件。  
5. **二次模型调用**：灵叙每段正文后再打一枪做场景分析。DSH 一轮 step 通常一次主模型请求；要二次调用就得自己开 LLM 或塞进 turn 后副作用。  
6. **版本漂移**：DSH 无兼容承诺。绑死上游版本、用 profile 自测，是生存问题，不是优化项。

### 1.4 本仓库现状

`InfiniteDSH` 目前是空目录。设计、插件包、preset、文档都还没落地。灵叙品牌不可用于本项目对外名称。

## 3. 逐题质询

### Q1 — 这个项目成功时，它是什么？

这是整棵树的根。选错后面所有「像不像灵叙」的争论都是噪音。

| 选项 | 含义 | 后果 |
|---|---|---|
| A. 自己用的写作运行时 | 你在 DSH Web / headless 里写自己的故事 | 体验优先，社区包装可后置 |
| B. 给 DSH 社区看的示范插件 | 展示垂直领域怎么用 bundle / preset / section / event | 代码要干净、可安装、README 要能让陌生人跑起来 |
| C. 灵叙的 DSH 移植 | 书架、开局卡、阅读器、导出尽量还原 | 工作量接近再做一个前端产品 |
| D. 可组合叙事引擎 | 世界书 / 角色 / 护栏 / 开局是能力，UI 能少则少 | 最贴 DSH 理念，第一期就能跑通 |

**推荐：A + D，对外按 B 的安装体验来收口。**  
成功标准写成：在官方 `dsh web` 上 `plugin add` 之后，用一个文学 preset 开出第一本故事，写 20 回合不串设定，能导出不含指令痕迹的 TXT。不把「打开就是书架」当第一期成功标准。

不推荐 C 作第一期目标：DSH Client 扩展点能改对话行，不能廉价地换掉整套 IA。

### Q2 — 交付形态

依赖 Q1。

| 选项 | 形态 | 优点 | 代价 |
|---|---|---|---|
| P0 纯 Host 插件 | 提示词段落 + 命令 + 工具 | 最小、稳定 | Web 里仍是编码聊天脸 |
| **P1 Host bundle + 文学 preset** | P0 + 收起编码工具 + 默认叙事提示 | 最贴「一切皆插件」 | 书架/阅读器仍弱 |
| P2 P1 + Client 对话节点 | 正文按小说排、推荐可点 | 书内体验接近灵叙 | 要跟 DSH client 包版本共舞 |
| P3 独立 Web 产品 | 自绘书架，只把 DSH 当内核 | 产品完整 | 不再是「一个插件」，维护面爆炸 |

**推荐：第一期 P1，预留 P2 的事件契约。**  
也就是：Host 先把「模型看见什么」做对，并留下可重放的 session 事件；Client 渲染以后再加，不要第一期就重做书架。

### Q3 — 第一期能力切割

依赖 Q2。下表是推荐切法，你可以整行推翻。

| 灵叙能力 | 推荐 | 理由 |
|---|---|---|
| 规则书：常驻 + 关键词注入 | **必做** | 这是「不像闲聊」的主因 |
| 故事绑定规则书，切书不串世界 | **必做** | 灵叙踩过的坑，DSH 更容易犯 |
| 叙事防护 / 剧情推进 | **必做** | 成本是两段 prompt，开关即可 |
| 只出正文 | **必做** | 否则导出是垃圾 |
| 开局：题材 / 世界 / 主角（简化） | **必做** | 没有开局就没有故事身份 |
| 角色卡（精简字段） | **必做** | 可先不做抽取，只做手写卡 |
| `/export` 干净 TXT | **必做** | 灵叙的「作品层」最小集 |
| 随机世界事件 | 第一期可做 | 纯本地抽卡，便宜 |
| 场景条 + 3 条推荐 | **降级** | 不要默认二次模型调用；能解析就解析，不能就没有 |
| 角色后台进展 | **后置** | 强依赖二次调用，还要对玩家隐藏 |
| 书架网格 / 封面 / 插画 | **砍** | DSH 侧栏会话列表顶上 |
| 阅读器纸色 / 字体 / 夜间 | **砍** | 用 DSH 主题 |
| 独立格式分析模型 | **砍** | 用主模型或没有 |
| 压缩后续卷 + 旧卷只读 | **降级** | 先用 DSH compaction + 档案段落 |
| 稿纸模式 | **砍** | DSH 本身就是稿纸 |
| 多供应商设置 / MCP / WebDAV / 安卓 | **砍** | DSH 已有模型与凭据 |
| 同世界再开一本 | 第二期 | 有故事绑定之后是一行命令 |
| 内置十几本规则书全文 | **降级** | 先带 2～3 本示范书，其余用户自建 |

### Q4 — 「一本故事」落在哪

依赖 Q2。这是数据模型的根，选完才能谈世界书绑定。

| 选项 | 做法 | 风险 |
|---|---|---|
| S1 一个 DSH session = 一本书 | 最简单 | 压缩/fork 之后「书」会裂 |
| **S2 workspace 目录 = 一本书，session 是书的一次书写** | `stories/<id>/` 放规则、角色、正文、meta | 要自己维护「当前书」 |
| S3 自建 SQLite，模仿灵叙 | 迁移最像 | 和 DSH 日志双写，违背「模型可见 ⟺ 日志」 |
| S4 只在 session 事件里堆 story/* | 重放漂亮 | 没有打开的 session 时书架是空的 |

**推荐：S2 为主，S4 为辅。**  
书的权威状态在工作区文件里（可版本管理、可导出、可备份）。当前打开哪一本、本轮命中了哪条规则，写成 session 事件，这样重放和 UI 都能用。不要再引入一套 SQLite。

「切书不串世界」的不变式：本轮组装规则书时，只读 `story.worldBookId` 指向的那一本书，禁止读全局 last-active。

### Q5 — 编码工具开不开

依赖 Q2。文学 Agent 误改磁盘是真实事故，不是风格问题。

| 选项 | 做法 |
|---|---|
| T1 完全关掉 bash / fs / 子代理 | 最安全，最不像「超级 Agent」 |
| **T2 文学 preset 默认只留：读工作区故事文件 + 本插件的叙事工具** | 模型可以整理规则书，但不能乱扫主盘 |
| T3 全开，靠 prompt 约束 | 必翻车 |
| T4 双 preset：`infinite-play` 与 `infinite-author` | 最灵活，第一期可以只做 play |

**推荐：T2，并在文档里预告 T4。**  
玩的时候模型不该有 bash。写设定的时候可以另开 author preset。第一期不要两个都做满。

### Q6 — 世界书 / 角色卡格式

依赖 Q4。

灵叙条目字段很多：`key` / `keysecondary` / `constant` / `order` / `insertionDepth` / `position` / `category`… 第一期用不完。

**推荐最小格式（Markdown + 前置元数据）：**

```markdown
---
id: sect-rules
title: 宗门戒律
constant: false
keys: [宗门, 外门, 戒律]
order: 10
---
外门弟子不得夜闯藏经阁。违者废去三年修为。
```

角色卡同样是一篇 md：`name` / `trigger` / `personality` / `speech` / `secrets`。

不要第一期兼容 SillyTavern / 灵叙 JSON 导入。有人真要再做转换器。

注入算法可以直接移植灵叙的：常驻优先，关键词命中，按 order 截断到 `maxChars`（默认 8000）。这是纯函数，最好单测。

### Q7 — 开局做到哪

依赖 Q3、Q4。

灵叙是四步卡牌：题材 → 世界底座 → 主角 → 开书。DSH 没有这种全屏向导。

| 选项 | 做法 |
|---|---|
| O1 `/new` 然后 AskUserQuestion 三问 | 最像 DSH |
| O2 用户自己准备目录，插件只认文件 | 最稳，最不友好 |
| O3 复刻卡牌 UI | Client 大工程 |
| **O4 `/new <题材>` 带缺省，可再 `/bind` `/cast`** | 命令可脚本化，也适合 headless |

**推荐：O4 + 少量 AskUserQuestion。**  
`/new 修仙` 立刻创建 `stories/<id>/`，写入默认规则书副本、默认主角、开篇种子，并绑定当前 session。不选就用内置缺省，不要把人堵在向导里。

随机开局 = 从内置题材里抽一套。同世界再开 = 复制规则书目录，新开 session。

### Q8 — 场景分析、推荐、后台进展

依赖 Q2、Q3。这里最容易偷偷把成本做高。

| 选项 | 做法 | 成本 |
|---|---|---|
| A0 全砍 | 只有正文 | 最低 |
| **A1 规则抽取，不做二次调用** | 正文后用启发式 / 可选结构化输出 | 低 |
| A2 灵叙原样：每段后再打一枪 | 章节 + 场景 + 3 推荐 + 后台 | 每回合双倍钱，还要处理失败 |
| A3 用户手动 `/analyze` | 按需 | 中 |

**推荐：A1，后台进展明确不做。**  
若模型愿意以约定的不可见尾注输出场景（生成后再剥掉），可以填场景条；失败则没有，正文照样能读。对话推荐第一期可以是静态「继续 / 观察 / 离开」或没有。点选推荐 = `agent.followup(那句话)`，这点 DSH 天然支持。

不要默认每回合二次 LLM。那是灵叙桌面端的奢侈，不是插件的默认。

### Q9 — 长篇记忆

依赖 Q4。

灵叙：到阈值后「整理记忆」→ 抽角色、写档案、锁旧卷、开新卷，书架仍是一张卡。

DSH：已有 compaction 接缝，自动压力在 `agent/pre-step`。

| 选项 | 做法 |
|---|---|
| C1 只用 DSH 默认压缩 | 省事，摘要不像「剧情档案」 |
| **C2 在 compaction 前后挂钩：产出故事档案 md，再注入** | 借官方接缝，保留文学结构 |
| C3 复刻「旧卷只读 + 新 session」 | 要自己做卷链，和 S1 裂书问题缠在一起 |

**推荐：C2。**  
书仍是那个目录。压缩结果写成 `stories/<id>/archive.md` 与 `characters/*.md`。旧文本可以留在 `chapters/` 里当作品层，不靠锁 session 来表达「上一卷」。

### Q10 — 仓库、命名、版本

依赖以上全部。

**推荐仓库形态：**

```
InfiniteDSH/
  packages/
    infinite-core/          # 世界书/角色/护栏纯函数，零 Cordis
    dsh-infinite/           # Host 插件：section / command / event / 工具
    dsh-infinite-preset/    # 文学 preset 与示范规则书
    dsh-infinite-client/    # 第二期：对话节点（第一期可空）
  examples/
    play.cordis.yml
  docs/
  README.md
```

- 包名：`dsh-infinite`（或你定的品牌）。不要叫 narra / airp / 灵叙。  
- DSH 当 peer，钉到你本机正在用的那一版，README 写明。  
- 测试：`infinite-core` 纯单测不需要 DSH；组装用 `--patch` 做 keyless 冒烟。  
- 许可：MIT，NOTICE 里致谢灵叙思路与 MIT 源码借鉴，不使用其品牌与插画。

## 4. 若按推荐走，第一期用户路径

1. `dsh plugin --profile infinite add <本包>`  
2. `dsh --profile infinite web`  
3. 新会话自动（或手动）挂上 `infinite-play` preset  
4. `/new 修仙` → 工作区出现一本故事，规则书与主角就位  
5. 用户输入行动，模型只出正文；命中「宗门」时注入戒律  
6. `/export` 得到无指令、无推荐、无系统标签的 TXT  
7. `/new 末世` 再开一本；回到第一本时注入的仍是修仙书

验收不看封面好不好看。看：两本书切换后，模型有没有把末世丧尸写进宗门。

## 7. 共识摘要（Q1–Q10 已锁）

InfiniteDSH 是树外 DSH 插件（`dsh-infinite`），不是独立软件，不移植灵叙 UI。

- 一本故事 = 一个文学会话；侧栏切会话即切书。
- 文学 preset 关掉 bash / 改文件 / 子代理。
- `/new [题材]` 把模板全套拷进该会话专属目录；之后只读这份副本。
- 必做：规则书注入、不串世界、护栏、只出正文、开局、手写角色卡、`/export`、随机世界事件。
- 长篇走 DSH compaction，档案写入会话目录，不续卷。
- 不做：书架、阅读器、场景分析/推荐/后台、独立分析模型、灵叙备份导入。

## 1. 我额外看到、你没点名的坑

这些不修，只改中文/卡片也会继续像半成品。

1. **卡片脚本在你这台机上等于没装上。** 我们做了 19 张世界封面 + 角色图，但依赖 `tapIndex` 注入 `cards.js`，再去改 DSH 问答的 DOM。你用了第三方皮肤（女仆鲸背景）。脚本认的是 `button[role=radio]` 且至少 2 项。皮肤一改 DOM，或只剩 1 个选项，封面全废。这是架构脆弱，不是「图没生成」。
2. **末世没有角色卡。** 开书第二步必然寒酸。其它题材角色卡也薄（有的只有 1～2 张）。
3. **开书拆成 3 次 AskUserQuestion。** 灵叙是一屏封面墙。DSH 官方问答是小对话框 +「跳过本题」。即使用上封面，也仍是三次弹窗，不像选卡。
4. **占位符、权限条、欢迎语全是编码产品。** 「描述你想要构建的内容」「Full access」「探索未至之境」。选了 Infinite Play 也不换。要换，得做 **client 插件** 或找 DSH 有没有 preset 级 composer 文案钩子。
5. **会话标题被第一句玩家话污染。** 「开始」成了书名。
6. **权限仍是 Full access。** Infinite Play 已经 `tools.restrict({ allow: [] })`，UI 还显示可写工作区，吓人且不像读书。
7. **Think / 系统提示出现在对话里**（图 5）。文学模式应尽量只留正文。
8. **斜杠菜单是全球命令表。** 文学会话里仍露出 `goal`、`permission`、官方 `export`。我们删不掉别人的命令，只能把自己的写清楚，或做自己的工具条。
9. **旧锁和你现在的期望打架。** 当初锁定：插件不是独立软件、不做灵叙 UI、不列选项、一本书=一个会话。你现在要卡片墙、选完就开写、回合后有下一步。这是升舱，不是修 bug。必须重锁，否则会做成四不像。

## 2. 和灵叙的真实差距（别幻想能一比一）

灵叙：**书架 → 封面选题 → 一本书的阅读器 → 回合选项/行动 → 导出作品。**

我们现在：**DSH 会话列表 → 手选 preset → 斜杠 `/new` → 官方问答框 → 普通聊天里出正文。**

DSH 能稳定用的官方钩子：

- 斜杠命令 + `userQuestions.ask`（就是你看到的「开书」小窗）
- `systemPrompt` 注入规则书
- agent preset 文案 / 禁工具
- 很脆的 `tapIndex` 改 HTML

DSH **没有**（除非做 client 包）：自定义首页、封面墙路由、回合末选项条、隐藏官方 `export`、改「描述你想要构建的内容」、改 Full access 文案。

所以下一步只能三选一，后面所有卡片/自动开写/选项都挂在这一刀上。

## 4. 决策正文

### Q1 — 这一期把体验做到哪一层？

**A. 壳内打磨（推荐先做，周期短）**  
中文 Infinite Play；`/new` 不带参必出题材问答；修 `cards.js`（1 张卡也显示封面；DOM 选择器按你现在的皮肤加强）；主角/开局文案去掉「Other」；空题材补默认角色卡；`/new` 成功后**自动代打第一句开场**（或内部触发一回合），不再停在空输入框；命令中文写清楚，`export-story` 改成「导出正文」。  
做不到：真正的封面墙首页、和灵叙一样的阅读器、藏掉官方 `/export`。

**B. 混合（推荐作为「像那么回事」的目标）**  
A 全部要。另外做 **client 插件**：选了 Infinite Play 或本会话已有 `meta.yml` 时，用我们的封面网格替换/覆盖问答列表；开书完成后自动切到「正文 + 行动条」。图真正用在选世界上。工作量和翻车面都大于 A（皮肤、DSH DOM、HMR）。

**C. 独立阅读壳**  
等于第二款软件。与旧锁冲突。除非你改口「可以做一个挂在 DSH 上的完整 UI」。

**推荐：先锁 B 的目标，但分两刀交付——第一刀必须是 A 且当天能感到「选完就开写 + 中文 + 封面至少在问答里露脸」；第二刀才上 client 封面墙。**  
若你只要一刀、要快：只做 A。

### Q2 — 封面用在哪？（Q1 之后）

- **A1** 继续寄生官方问答 radio，把 19 张世界封面铺进「选题材」。角色/开局能配图的配图。失败则退回列表。  
- **B1** client 里自绘封面墙，点卡即选，不靠改 radio。  
- **A2** 问答里只做大号图+短名，不做网格（更稳，没那么像卡）。

**推荐：Q1=A 则 A1；Q1=B 则 A1 先保底，B1 作第二刀。**

### Q3 — 选完题材/主角/开局之后？

- **立刻写第一段**（推荐）。`/new` 结束后插件代发一个开场回合（文案可固定「按开篇写下去」），用户看到的是正文，不是空框。  
- **弹出「开始 / 换开局 / 换主角」三键**，点开始才写。  
- **维持现状**，提示用户自己打第一句。

立刻开写会少一次操作，但也少一次反悔。会话标题应改成书名/题材，不要用「开始」。

### Q4 — 每段正文后面要不要选项？

这是对旧锁「禁止列选项 / 不做对话推荐」的翻案。

- **D1 不要选项**（维持小说态）：你只打行动。最像「写书」，最不像「文字冒险游戏」。  
- **D2 软选项**：正文末由**同一轮模型**附 3 条短行动（仍是正文里的句子，或单独一块「你可以」）。有游戏感，有时会破「只出正文」。  
- **D3 硬选项**：正文后另开 `userQuestions` 三选一 + 自定义。最像灵叙，最吵，也最容易和「跳过本题」打架。

**推荐：第一刀 D1 + 自动开写；若你明确要「玩」大于「写」，第一刀就上 D2。** 不建议一上来 D3。

### Q5 — 斜杠命令怎么让人看懂？

- 全部文学命令改中文短句：`开书`、`换规则书`、`换主角`、`导出正文`。  
- `export-story` 改名为更不像官方的 `story` / `书稿`（DSH 命令名通常要英文小写，**显示名**可以中文）。  
- 文学会话里无法删除官方 `export`，只能在我们的说明里写「那个是日志包，这个才是小说」。

**推荐：保留英文命令名（兼容），重写 description 为中文一句人话。**

### Q6 — 空壳题材补多满？

末世现在 0 张角色卡。修仙有几张。深海实验室最满。

- **只补空的**：每界至少 1 张默认主角立绘 + 3 张开局（保证卡片网格能亮）。  
- **按灵叙密度补**：大工程。  
- **先不管卡，只保证默认主角也有封面。**

**推荐：只补空的 + 默认主角必有图。** 图已经在 `covers/`，缺的是角色卡文件和映射。
